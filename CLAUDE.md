# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The website for **Aurette by Mia**, a Melbourne home bakery — a static, no-build,
vanilla HTML/CSS/JS site (three visitor pages + an owner admin page) designed to
cost $0/month. There is **no bundler, no framework, no package.json at the root**:
files are served as-is by GitHub Pages today, with a Cloudflare Worker
(`src/worker.js` + `wrangler.jsonc`) ready as the target host. Do not introduce a
build step.

The "database" is `data/products.json` + `data/settings.json`. The owner edits
them through `admin.html`, which commits via the GitHub Contents API using a
fine-grained PAT stored in her browser — so **any new product field must survive
that round-trip**. `js/admin.js` mutates the loaded product objects in place and
re-serializes the whole array, which is what keeps extra fields like
`video`/`videoPoster` intact; never refactor it to rebuild products from form
fields alone.

## Commands

Everything runs from `tools/` (the only npm package in the repo):

```bash
cd tools && npm install          # once; set CHROMIUM_PATH if Playwright's browser lives elsewhere
npm test                         # smoke3 (3 pages) + wipetest — assert zero page errors
npm run test:video               # hover-video behaviour (generates VP9 twins first — see below)
node smoke3.js                   # a single suite; screenshots land in tools/out/
npm run og                       # rebuild images/og.png from images/brand/logo.png
```

Local preview of the site itself: `python3 -m http.server 8000` from the repo root
(pages `fetch()` the JSON, so `file://` won't work).

Test quirks worth knowing:
- Each suite starts its own localhost server and **routes the GSAP CDN to the
  local npm copy** — sandbox proxies often block jsdelivr; don't "fix" a blocked
  CDN by editing the pages.
- Playwright's Chromium has **no H.264 decoder**, so `videotest.js` plays VP9
  re-encodes from `tools/testmedia/` (generated by `gen-testmedia.js`). The shipped
  site uses H.264 on purpose — every real browser plays it; do not switch the
  production files to VP9 (old iPhones) or conclude from a headless failure that
  the videos are broken.

## Architecture

### Progressive enhancement is the load-bearing wall

`js/motion.js` owns all animation and is layered strictly:

1. **`html.motion-on`** — set only when GSAP loaded *and* the user allows motion.
   Every cinematic layout state (pinned 340vh cake stage, hidden captions,
   ingredient choreography, page wipe, magnetic buttons, marquee) is gated on
   this class in CSS/JS.
2. **`html.io-anim`** — no GSAP but motion allowed: IntersectionObserver + CSS
   reveals only.
3. **Nothing** — reduced motion / no JS / blocked CDN: the full page renders
   static and complete. CSS must never hide content except under `.motion-on`
   or `.io-anim`.

When adding animation, follow the existing transform-layering pattern: e.g. hero
ingredients put scroll fly-out on the wrapper (`.ing-fly`), arrival fly-in + idle
bob on the inner `<img>`, so tweens never fight over one element's transform.
Collage entrances go through `dealIn()` (scatter + spin + `back.out`, random
stagger) rather than `revealIn()`; resting tilts live in CSS so the no-JS page
still looks pasted-up. The page wipe's five path states are all generated by
one `sheet()` function so they share a point structure and morph cleanly —
if you edit one, regenerate all five.

### The page wipe (cross-page transition)

Three cooperating pieces, all three pages: an inline `<head>` script sets
`html.wipe-hold` **pre-paint** when `sessionStorage.auretteWipe` exists (with a
2.2s failsafe timeout); `.page-wipe` markup + CSS shows the covering sheet;
`motion.js` intercepts same-origin clicks to `index/shop/about.html` only, plays
the curved-SVG cover, sets the sessionStorage flag, navigates, and on the next
page lifts the sheet. Every degraded path (reduced motion, no GSAP, bfcache
restore) must clear the flag/class — that cleanup already exists in
`motion.js`; keep it when editing.

### Card media ladder (shop)

`store.js` picks each product card's media: real footage (`p.video`,
chromeless muted `<video>`, hover-play on desktop / in-view on touch) →
the product's flat 2D illustration (`p.image`). Reduced motion always gets
stills; a missing video (or poster) falls back down the ladder. Cart
thumbnails and the IG-fallback gallery always use the static `p.image`.

### Ordering without a backend

Checkout builds a formatted order message and hands it to WhatsApp
(`wa.me/…` via `location.href` — popups die in Instagram's in-app browser) or
email. The earliest-pickup date comes from the max lead time in the cart, the
daily cutoff hour evaluated in `settings.timezone` (Intl), and
`closedWeekdays`; `earliestPickup()` returning `null` means every day is closed
→ ordering pauses. Cart lines snapshot `variantName` and are dropped on
mismatch after menu edits — prices are never trusted from stale storage.

### The collage system (current visual direction)

The site is a paper collage. Two rules carry it:

**Art** — every product, ingredient and kitchen tool is a magazine cutout in
`images/cutout/`, governed by `images/cutout/_spec.md`: a flat `#d9cbb6`
print shadow, a `#fffdf8` sticker rim with a RAGGED hand-cut edge, then flat
art, plus sparing halftone dots. No gradients, strokes, filters or opacity —
the sticker rim is drawn into the SVG rather than applied as a CSS filter
chain (cheaper, crisper, and it survives the no-filter rule). `images/flat/`
holds the previous plainer set, still valid as fallback art.

**Page** — `css/collage.css` loads last on every page and turns the furniture
into paper: `.scrap` (a torn sheet; note it uses `filter: drop-shadow` because
`clip-path` would clip a `box-shadow`), `.tape` (multiply-blended strips),
`.clipping` (stamped labels), `.scribble` (handwriting), plus one fixed
body-level grain overlay. Cards, buttons and headers are re-skinned there, not
in `style.css`.

Three type roles, each with one job: **Archivo** (`--font-display`/
`--font-body`) for structure, **Fraunces** (`--font-serif`) for the editorial
voice, **Caveat** (`--font-hand`) for the annotation layer ONLY — margin notes
and signatures, never anything required to complete an order. Caveat renders
small; keep it at 20px+ and slightly rotated.

`images/brand/logo-original-150.png` is the owner's untouched logo — every
other brand asset is a Lanczos resample of it; never redraw or "enhance" it.

### Theming

`css/themes/*.css` override the design tokens in `:root`; the inline head
script on every page applies `?theme=<name>` and persists it in localStorage.
New UI must use the tokens (`--bg`, `--accent`, `--ink`, …) so themes keep
working. `themes.html` is the picker.

## Conventions

- Keep the guidelines already applied: explicit `width`/`height` on every img
  (with `height: auto` in CSS where width is fluid — the attribute otherwise
  pins the height), curly quotes/ellipses in copy, Title Case buttons,
  `aria-hidden` on decorative layers, transform/opacity-only animation.
- `git push` to `claude/cake-shop-ordering-site-y3eogf` **and** `main` (Pages
  deploys from `main`; the owner has authorized pushing there).
- After UI changes, run `npm test` in `tools/` and treat any page error or
  horizontal-scroll report as a failure.
